## Коммиты

- не добавляй в сообщение коммита строки об авторстве (`Co-Authored-By`, «Generated with» и подобные);

- коммиты делай по паттерну:

```
{тип}: {что изменилось в поведении,  со строчной буквы, на русском языке}
```
где тип - feat, fix, build, ci, style, docs, refactor, chore (по https://www.conventionalcommits.org/en/v1.0.0/)

- преследуй правило 1 фича или одно исправление бага - 1 коммит, не плоди для одной логической задачи кучу коммитов, коммит должен отражать одно бизнес-изменение;

- в сообщении коммита не должны отражаться подробности реализации, название переменных, подробности из кода;

- при описании коммита пиши понятные конструкции слов на русском языке не пропуская слова и глаголы, другие разработчики и пользователи должны нормально понимать, что приносит то или иное изменение продукту;

- описание коммита должно быть от третьего лица (сделано, добавлено, исправлено);


Пример плохих коммитов:

`feat: add zustand store with persistence`
`fix`
`fix: кнопка удаления`
`feat: исправлен баг`


Пример хорошего коммита:

`feat: добавлена кнопка для импорта данных в календарь из json-файла`
`fix: исправлен формат данных при экспорте, из-за чего при повторном импорте крашилось приложение`

## Ветки

Ветки создавай от `main`. Называй по паттерну {тип}/{краткое-описание}, например:

`feat/delete-button`
`fix/crash-after-tab`
`refactor/update-arch`

## Общие правила

- Не пуш в удаленный репозиторий без разрешения
